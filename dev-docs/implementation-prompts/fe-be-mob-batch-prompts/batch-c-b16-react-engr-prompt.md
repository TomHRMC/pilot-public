## Design Decisions (Do Not Re-Litigate)

From design doc §G and the approved specs — these are final:

| # | Decision | Outcome | Source |
|---|---|---|---|
| 1 | Public pages are SSR with server-side fetch | **Exception to rules §35.** The tenant-site pages hit `GET /api/v1/public/tenant-sites/{slug}` — an unauthenticated, rate-limited, cacheable public endpoint. SSR is a product requirement (TCR vets + SEO indexing). The `apiClient`-only rule applies to *browser* calls; the server fetcher uses `fetch` with Next.js cache (`revalidate: 300`) | §G-6, §D-7, mkt spec §1 |
| 2 | Page bodies render `body_paragraphs` | Pre-escaped plain-text paragraphs from the published snapshot. **No markdown parser, no `dangerouslySetInnerHTML`** — injection-safe by construction | §G-6 |
| 3 | `src/middleware.ts` is a NEW file | None exists today. Host-rewrite must be matcher-scoped to the sites domains ONLY — it must not intercept existing auth/api/app routes. Local dev: treat `*.localhost` hosts as sites hosts + support `?__slug=` override | §G-13 |
| 4 | Option 3 (Starter Site) | Ships as the **disabled-card treatment** (real description, `aria-disabled`, `tabIndex={-1}`, `cursor-not-allowed`) — Tom-approved resolution of web spec §21 item 1. No bare "coming soon" string | web spec §6.3.6 |
| 5 | Public 404 state | Neutral, Pilot-branded only — **no "Hosted by" footer** (footer would leak that a site could exist at the slug) | mkt spec §1.3 |
| 6 | Privacy/Terms "last updated" line | `text-neutral-500` (4.8:1 AA) — approved mkt spec §14.2 recommendation, overriding the pixel spec's `text-neutral-400` | mkt spec approval |
| 7 | Slug mutability | Editable only while never-published; immutable after first publish (backend enforces; UI disables + explains) | §G-7 |
| 8 | Overwrite confirmation | Publish over a tenant-entered 10DLC `website` returns **409 `website_overwrite_requires_confirmation`** → dialog shows current vs. new URL → re-POST with `confirm_website_overwrite: true` | §G-16, web spec §10 |
| 9 | Option-1 email | One-time automatic backend send — **no resend button anywhere**. UI shows "Guide emailed on {date}" + PDF download link only | §G-19 |
| 10 | No new `packages/ui` components | `DefaultsAnnotatedField` and all batch components are feature-local (`apps/web/src/features/tenant-site/`) | web spec §18 |

These were resolved in the design doc and approved specs. Do NOT change them without asking Tom.

import { http, HttpResponse } from "msw";

export const tenantSiteHandlers = [
  http.get("/api/v1/tenant-site", () =>
    HttpResponse.json({ configured: false, defaults: { /* display_name, public_phone, ... */ } }),
  ),

## STEP 2 — `src/middleware.ts` (host rewrite — NEW FILE, highest-risk step)

- **Read first**: there is no existing `middleware.ts` — you are creating the app's only one. Next.js 16 runs it for every matched request.
- Extract pure logic to `src/lib/tenant-site-host.ts` for testability: `parseSitesHost(hostname: string): { slug: string } | null` — matches `{slug}.{NEXT_PUBLIC_TENANT_SITES_DOMAIN}`, `{slug}.localhost` / `{slug}.localhost:3000` (dev), and rejects apex/www/reserved hosts.
- `middleware.ts`: on a sites-host match, rewrite to `/sites/{slug}{pathname}` preserving the URL; support `?__slug=` dev override per design §G-13. On non-match, `NextResponse.next()` untouched.
- **Matcher config must be scoped**: exclude `api/`, `_next/`, `i/`, `q/`, `login`, `signup`, `operator`, and all `(authed)` paths — the middleware must be a no-op for the entire existing app. (Design §I: "must NOT intercept existing auth/api paths.")
- **Unit tests** for `parseSitesHost` (prod domain, localhost, apex rejection, reserved-slug rejection, port handling) — this is pure logic, fully testable in Vitest.
- **Intermediate verification**: `pnpm --filter web test -- apps/web/src/lib 2>&1 | tail -8` + run the **full web suite** once (`pnpm --filter web test 2>&1 | tail -6`) to prove zero interference with existing routes.
